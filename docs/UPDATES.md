# GitHub 자동 업데이트 · 배포자 안내

## 클라이언트가 보는 곳

Apple Silicon용 메뉴 앱은 다음 URL 하나를 기준으로 버전을 확인합니다.

`https://raw.githubusercontent.com/kcc920926-droid/capsflow/main/updates/latest-arm64.json`

파일은 평문 버전 문자열이 아니라 **Ed25519 서명 봉투**입니다. `payload`는 버전·빌드·CPU·최소 OS·
릴리스 주소·ZIP 주소·바이트 수·SHA-256을 담은 JSON의 Base64, `signature`는 그 원문 바이트의 서명입니다.
검증한 페이로드만 사용하며 설치된 앱보다 낮은 버전·빌드는 거부합니다. CPU별로 피드를 분리하고,
현재 배포·검증한 아키텍처는 arm64입니다.

앱 실행 중 기본 6시간마다 확인합니다. 실패 시 30분부터 최대 하루까지 간격을 늘리고, 성공하면
6시간으로 초기화합니다. 앱이 종료돼 있으면 별도 데몬이 계속 조회하지 않습니다.
자동 확인·자동 다운로드는 메뉴에서 끌 수 있고 수동 확인은 항상 가능합니다.
앱은 쿠키·인증 정보를 보내지 않는 임시 URLSession을 사용하며 입력 내용은 전송하지 않습니다.

자동 다운로드 후에도 설치는 직접 확인해야 합니다. 입력기 교체는 사용 중인 글자를 잃을 수 있어
현재 ‘자동’ 사용 시 설치 파일 열기를 막고 ABC·두벌식 전환을 안내합니다. 설치기에서도 입력 저장
확인·안전한 종료·백업·등록 대기를 다시 적용합니다. 권한 승인·재로그인은 강제하지 않습니다.

## 서명 키

소유자 승인을 받아 이 Mac의 로그인 키체인에 전용 키를 만들었습니다.

- Keychain service: `local.capsflow.release-signing.ed25519`
- account: `primary-v1`
- 공개키: 배포 앱의 `CapsFlowUpdatePublicKey` (Resources/Info.plist)
- 개인키: **키체인에만 보관**. 앱·설치 ZIP·Git·GitHub에는 포함하지 않습니다.

`scripts/update-signer.swift`는 키를 읽어 서명하고, 공개키만 출력합니다. 자동 키 생성은
`--init-key`를 명시했을 때만 가능하며 이미 있으면 기존 키를 재사용합니다. `prepare-update.sh`는
새 키를 만들지 않고, 키체인의 공개키가 앱에 들어간 공개키와 다르면 중단합니다.
개인키를 출력하거나 평문 파일로 내보내는 옵션은 제공하지 않습니다.

Mac 재설치·기기 변경 전에 **로그인 키체인의 안전한 백업·이전**을 준비하세요. 키를 잃고 소스의
공개키만 바꾸면 기존 사용자는 새 서명을 검증할 수 없습니다. 개인키를 채팅·이슈·저장소에 올리지 마세요.
이 서명은 업데이트 발행자 확인용이며 Apple Developer ID 서명·공증을 대체하지 않습니다.

## 새 버전 배포 순서

1. `Resources/Info.plist`의 버전과 빌드 번호를 올립니다. `CFBundleVersion`은 이전보다 커야 합니다.
   공개키는 유지하세요. 필요하면 입력기 버전도 별도로 올리되 메뉴 앱 버전·빌드를 반드시 올립니다.
2. 입력·업데이트 정책·설치기 검사를 수행합니다. 실제 사용자 앱을 교체하는 검사는 별도로 승인을 받습니다.

   ```sh
   swift run CoreChecks
   swift run UpdateChecks
   zsh scripts/test-setup.zsh
   ```

3. 설치 ZIP과 서명 매니페스트를 만듭니다.

   ```sh
   zsh scripts/package-installer.sh
   zsh scripts/prepare-update.sh
   ```

   `dist/`에 설치 ZIP, `.sha256`, `latest-arm64.json`이 생깁니다. 서명 도구가 없으면 컴파일하고,
   키체인에서 기존 키를 읽습니다. macOS가 키체인 확인을 요구하면 소유자가 직접 승인하세요.
   로컬 점검은 발행자 서명·ZIP 해시·압축 경로·확장 크기·앱 버전·앱 서명까지 확인하지만
   **설치 파일을 실행하거나 현재 앱·입력 소스·권한을 바꾸지는 않습니다.**
4. 소스 커밋·태그를 올리고 해당 버전의 GitHub Release에 ZIP·SHA-256·서명 JSON을 첨부합니다.
   Apple 공증 전 개발판이라는 상태와 검증 범위를 릴리스 설명에 유지하세요.
5. **릴리스 ZIP을 먼저 공개하고 다운로드 무결성을 확인한 뒤**, `dist/latest-arm64.json`을
   `updates/latest-arm64.json`에 반영해 커밋·푸시합니다. 파일 내용은 서명 뒤 고치면 안 됩니다.
   아직 받을 수 없는 ZIP을 공개 피드에서 먼저 가리키지 마세요.
6. 공개 경로 전체를 읽기 전용으로 점검할 수 있습니다.

   ```sh
   ./dist/CapsFlow.app/Contents/MacOS/CapsFlow --verify-remote-update
   ```

   공개 피드 → 서명 검증 → ZIP 다운로드·해시 → 경로·해제 크기·앱 버전·서명 검사까지 수행합니다.
   점검용 임시 폴더만 만들며 설치기를 실행하지 않습니다. GUI 권한이나 실제 키 입력 검증을 대신하지 않습니다.

## 안전 경계와 제한

- 앱에는 공개키만 들어 있으므로 GitHub 원문 파일이나 해시 파일만 바꾸어도 유효한 업데이트가 되지 않습니다.
- HTTPS의 GitHub/raw.githubusercontent.com/공식 릴리스 자산 호스트만 사용하고 다른 저장소·쿼리 주소는
  페이로드에서 거부합니다. 정상 CDN 리다이렉트에는 GitHub가 붙이는 임시 서명 쿼리가 있을 수 있습니다.
- 메타데이터 최대 32KiB, ZIP 최대 64MiB, 해제 크기 최대 256MiB/10,000개 항목입니다.
  경로 탈출·심볼릭 링크·중복 파일을 거부하고 앱 식별자·메뉴 앱 실제 버전·코드 서명을 확인합니다.
- 새 버전 통지는 메뉴바의 ↑와 메뉴 항목으로 표시해 타이핑 중 창을 반복해서 띄우지 않습니다.
  사용자가 직접 확인을 눌렀을 때만 결과·설치 확인 창을 띄웁니다.
- 이 첫 구현은 Developer ID 공증·무인 교체·서명 키 자동 회전을 제공하지 않습니다.
  새 계정에서의 최초 설치·TCC 승인·실제 이전 버전 교체 검증은 별도 작업입니다.
