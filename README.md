# CapsFlow

Caps Lock으로 한글·영문·자동 입력을 전환하는 macOS 앱입니다. 기본은 **3단계: 한 → EN → 자동**이며, **Speed: 한 ↔ EN**도 선택할 수 있습니다.

[간편 설치 ZIP 다운로드 · Apple Silicon](https://github.com/kcc920926-droid/capsflow/releases/download/v0.3.2/CapsFlow-Installer-0.3.2-arm64.zip) · [빠른 설치](#빠른-설치) · [설치가 막힐 때](#설치가-막힐-때)

설정창의 **Caps Lock 동작** 또는 메뉴바에서 선택하세요. 기본은 기존 3단계이며, 설정 변경은 현재 입력 모드를 바꾸지 않습니다. Speed 설정에서 수동으로 ‘자동’을 선택했다면 다음 Caps는 EN입니다. ‘Speed’는 한 번에 두 모드만 오가는 동작 이름으로, 속도 측정 수치를 뜻하지 않습니다. [검증 기록](VALIDATION.md) · [모바일 그림](docs/overview-mobile.svg)

## 빠른 설치

**[간편 설치 ZIP 받기 — v0.3.2 / Apple Silicon](https://github.com/kcc920926-droid/capsflow/releases/download/v0.3.2/CapsFlow-Installer-0.3.2-arm64.zip)**
([릴리스 안내·SHA-256](https://github.com/kcc920926-droid/capsflow/releases/tag/v0.3.2))

메뉴 앱 0.3.2 + 한국어 우선 입력기 0.2.3이 포함된 **개발용 프리릴리스**입니다.
현재 패키지는 Apple Silicon 전용이며, Developer ID 서명·Apple 공증 전입니다.

**압축을 풀고 `Install.command`를 더블클릭하세요.** 빌드가 필요한 경우에는 빌드부터,
두 앱의 복사·입력기 등록·메뉴 앱 실행까지 한 흐름으로 진행합니다.

| 받은 파일 | 준비물 | 실행 방법 |
| --- | --- | --- |
| 별도 배포용 `CapsFlow-Installer-버전-arm64.zip` | 빌드 도구 불필요 · Apple Silicon용 | 압축 해제 → `CapsFlow-Installer/Install.command` 더블클릭 |
| GitHub **Code → Download ZIP** 또는 `git clone`으로 받은 소스 | Swift 6 이상 Command Line Tools | 압축 해제 → 저장소의 `Install.command` 더블클릭 |

GitHub의 **소스 ZIP과 설치 ZIP은 다릅니다.** 설치 ZIP에는 `apps` 안의 두 앱과 `bin` 안의
도우미가 들어 있습니다. 소스에서 시작할 때 빌드 도구가 없다면 먼저 `xcode-select --install`로
설치하고 다시 실행하세요. 현재 패키지는 로컬 ad-hoc 서명이며 Developer ID 서명·Apple 공증이 아닙니다.
macOS가 차단하면 배포 출처를 직접 확인하고 시스템 안내를 따르세요. 보안 기능을 끄거나 일괄 우회하지 않습니다.

터미널에서는 저장소 또는 설치 패키지 폴더에서 한 줄로 시작할 수도 있습니다.

```sh
zsh ./scripts/setup.sh
```

설치기가 멈췄을 때 직접 해야 하는 일은 다음과 같습니다.

- **입력 소스 추가가 필요함**: 시스템 설정 → 키보드 → 텍스트 입력 편집 → ＋ → 한국어 →
  CapsFlow 한국어 우선 → 추가. 목록에 없으면 작업 저장 후 로그아웃·로그인하고 추가하세요.
  그다음 **같은 `Install.command`를 다시 실행**하면 이어서 진행합니다.
- **사용 중인 입력기 교체가 필요함**: 입력 내용을 저장하고 **ABC 또는 두벌식으로 전환**한 뒤
  다시 실행하세요. 실제 교체 전에는 다른 앱의 조합 중인 글자까지 확정·저장했는지 한 번 확인합니다.
  확인 후 `y` 또는 `예`를 입력하세요. 취소하면 앱을 종료하거나 교체하지 않습니다.
  설치기가 현재 입력 소스를 강제로 바꾸거나 사용 중인 입력기를 덮어쓰지 않습니다.
- **macOS 권한 요청**: CapsFlow의 **손쉬운 사용(접근성)·입력 모니터링**을 직접 허용하세요.
  설치기는 권한 DB를 고치거나 자동 승인하지 않습니다.

이미 같은 앱이 설치돼 있으면 교체하지 않습니다. 설정은 보존하며, 교체한 기존 앱은
`~/Library/Application Support/CapsFlow/Install Backups/` 아래에 보관합니다.
복사·검증 실패 때는 기존 앱을 유지하고, 새 앱의 최종 이동에 실패하면 가능한 경우 원래 앱을 복구합니다.
입력 소스 추가가 아직 안 됐으면 **기존 메뉴 앱은 교체하지 않고** 다음 실행을 기다립니다.

상태 확인만 하거나, 창을 열지 않고 설치하려면 다음을 사용하세요.

```sh
zsh ./scripts/setup.sh --check
zsh ./scripts/setup.sh --no-open
```

`--check`는 빌드·복사·등록·앱 종료·설정창 열기를 하지 않습니다. `--no-open`은 실제 설치는 수행하되
앱과 설정창을 열지 않습니다. 기존 입력기를 교체할 때의 입력 저장 확인은 터미널에서 직접 해야 합니다.
설치 후 메뉴의 **자동**을 선택해 `dkssud` + Space → `안녕`,
`hello` + Space → `hello`를 확인하세요.

배포용 ZIP을 직접 만들 때는 저장소에서 `zsh ./scripts/package-installer.sh`를 실행합니다.
결과는 `dist/CapsFlow-Installer-버전-CPU.zip`이며 **현재 빌드한 CPU용**입니다.
이 명령은 패키지만 만들고 현재 사용 중인 앱·입력 소스·권한은 변경하지 않습니다.
저장소의 `dist/`는 Git에 포함하지 않으므로 소스 ZIP을 설치 ZIP으로 오해하지 않도록 별도로 배포하세요.

처음 설치하는 분을 위한 **소스 다운로드 → 빌드 → 입력기 등록 → 메뉴 앱 설치** 안내입니다.
아래 명령은 터미널에서 실행합니다. 빌드나 복사에 오류가 나면 다음 단계로 진행하지 마세요.

CapsFlow는 두 앱을 함께 사용합니다. **메뉴 앱만 설치하면 ‘자동’ 입력을 사용할 수 없습니다.**

| 구성 | 하는 일 | 설치 위치 |
| --- | --- | --- |
| CapsFlow | 메뉴바, Caps Lock 전환, 긴 Backspace 처리 | `~/Applications/CapsFlow.app` |
| CapsFlow 한국어 우선 | ‘자동’ 모드의 한글 조합·영어 판정 | `~/Library/Input Methods/CapsFlowInputMethod.app` |

준비: macOS와 Swift 6 이상 빌드 도구가 필요합니다. Command Line Tools가 없다면
`xcode-select --install`로 설치한 뒤 `swift --version`을 확인하세요. 전체 Xcode 앱은 필수가 아닙니다.
패키지의 최소 대상은 macOS 13이지만, 실제 검증 환경은 **Apple Silicon · macOS 27.0.1 · Swift 6.4**입니다.
모든 macOS 버전이나 Intel Mac에서 설치·동작을 확인한 것은 아닙니다.

### 1. 소스를 받고 두 앱 빌드하기

```sh
git clone https://github.com/kcc920926-droid/capsflow.git
cd capsflow
./scripts/build.sh
zsh ./scripts/build-input-method.sh
```

이미 소스를 받았다면 해당 폴더에서 마지막 두 명령만 실행하세요.
빌드 결과는 `dist/CapsFlow.app`, `dist/CapsFlowInputMethod.app`입니다. 아직 설치된 상태는 아닙니다.

### 2. 자동 입력기 설치·등록하기

> 기존 설치를 업데이트하는 중이라면 먼저 **ABC 또는 두벌식으로 전환**하고 입력 중인 내용을
> 저장하세요. 메뉴바에서 CapsFlow를 종료하고, 기존 CapsFlowInputMethod 프로세스도 종료된 것을
> 확인한 뒤 교체하세요. 실행 중인 입력기를 그대로 덮어쓰지 마세요.

저장소 폴더에서 다음을 실행합니다. 사용자 Library에 설치하므로 이 과정에 `sudo`는 사용하지 않습니다.

```sh
mkdir -p "$HOME/Library/Input Methods"
ditto "dist/CapsFlowInputMethod.app" "$HOME/Library/Input Methods/CapsFlowInputMethod.app"
"$HOME/Library/Input Methods/CapsFlowInputMethod.app/Contents/MacOS/CapsFlowInputMethod" \
  --register "$HOME/Library/Input Methods/CapsFlowInputMethod.app"
```

등록 명령에 `log out/in`, `not visible` 안내가 나오면 아직 사용할 준비가 끝나지 않은 상태입니다.
파일을 다시 복사하는 대신 아래 단계에서 입력 소스를 추가하세요.

### 3. macOS 입력 소스에 추가하기

**시스템 설정 → 키보드 → 텍스트 입력의 편집 → ＋ → 한국어 → CapsFlow 한국어 우선 → 추가**로 들어갑니다.
이미 추가돼 있다면 중복 추가할 필요는 없습니다. 목록에 보이지 않으면 작업을 저장하고
**로그아웃한 뒤 다시 로그인**하여 같은 메뉴를 확인하세요. 이 Mac의 최초 설치에서도 재로그인이 필요했습니다.
기존 ABC·두벌식은 삭제하지 말고 유지하세요.

다시 터미널에서 저장소 폴더로 이동해 확인합니다.

```sh
./dist/CapsFlow.app/Contents/MacOS/CapsFlow --native-input-method-ready
```

**`CapsFlow native input method ready.`**가 나오면 다음 단계로 진행하세요.
`Native input method is not enabled`가 나오면 입력 소스 추가·재로그인부터 확인해야 합니다.

### 4. 메뉴 앱 설치와 권한 허용

저장소 폴더에서 실행합니다.

```sh
./scripts/install.sh
```

이 스크립트는 입력기 준비 상태를 확인한 뒤 메뉴 앱을 `~/Applications/CapsFlow.app`에 설치하고 실행합니다.
준비되지 않았다면 기존 메뉴 앱을 바꾸지 않고 중단합니다.

CapsFlow의 권한 안내를 따라 **시스템 설정 → 개인정보 보호 및 보안**에서 다음을 허용하세요.

- **손쉬운 사용(접근성)**: CapsFlow 켜기
- **입력 모니터링**: CapsFlow 켜기

항목을 직접 추가해야 한다면 `~/Applications/CapsFlow.app`을 선택합니다. 시스템이 관리자 인증을
요청하면 macOS 창에 직접 입력하세요. 권한은 메뉴 앱의 전역 키 처리에 사용됩니다.
소스를 다시 빌드해 앱을 교체하면 기존 항목이 켜져 있어도 재승인이 필요할 수 있습니다.

### 5. 처음 실행 확인

메뉴바의 CapsFlow에서 **자동**을 선택하고, 중요한 내용이 없는 빈 입력창에서
아래 키를 **붙여넣지 말고 직접** 입력해보세요.

| 입력 | 공백으로 확정한 뒤 결과 |
| --- | --- |
| `dkssud` + Space | `안녕` |
| `hello` + Space | `hello` |

자동 모드는 기본적으로 한글을 조합하고, `hello`처럼 명확한 영어는 **단어를 확정할 때** 영어로 돌립니다.
영어도 공백 전에는 한글 조합으로 보일 수 있습니다.

Caps Lock의 기본 동작은 **한 → EN → 자동**입니다. 한·영만 오가고 싶으면 설정의
**Caps Lock 동작 → Speed**를 선택하세요. 원격에서 Caps Lock이 전달되지 않으면
**⌃⇧Space(Control+Shift+Space)** 또는 메뉴의 전환 버튼을 사용할 수 있습니다.
로그인 시 자동 실행은 CapsFlow 설정에서 필요할 때 켜세요.

### 설치가 막힐 때

- **자동 입력기가 목록에 없음 / 메뉴 앱 설치가 중단됨**: 간편 설치 안내 또는 수동 설치 2~3단계를 확인하고, 필요하면 로그아웃·로그인 후
  입력 소스에 추가하세요. 메뉴 앱 설치만 반복해서는 해결되지 않습니다.
- **Caps Lock이 반응하지 않음 / 권한 대기 상태**: 설치된 CapsFlow 앱이 손쉬운 사용·입력 모니터링에
  등록됐는지 확인하세요. 재빌드 후에는 해당 항목을 다시 허용하고 메뉴 앱을 재실행해야 할 수 있습니다.
- **입력기 교체 뒤 특정 앱에서 글자가 입력되지 않음**: 먼저 ABC·두벌식으로 돌아가세요.
  미전송 내용을 보관한 뒤 해당 앱을 완전히 종료·재실행해 확인하세요. 이 Mac의 Codex에서는 이 방법으로
  복구됐지만 모든 앱에 같은 해결을 보장하지는 않습니다.
- **잠시 원래 입력 방식으로 돌아가기**: macOS 입력 메뉴에서 **ABC 또는 두벌식**을 선택하고,
  CapsFlow 메뉴 앱을 일시 정지하거나 종료하세요.

## 0.3.2 · 이번 버전에서 확인한 동작

- **기본 3단계**: Caps Lock으로 `한 → EN → 자동` 순환. 설정에서 Speed를 고르면 `한 ↔ EN`만 토글합니다. 이전에 고른 설정은 재실행해도 유지됩니다.
- **원격 전환**: Caps Lock 또는 `⌃⇧Space`로 같은 전환 정책을 사용합니다. 직접 연결된 키보드가 없어도 메뉴 앱을 유지합니다.
- **긴 Backspace**: 짧게 누르면 글자 삭제, 1초 이상 누르면 어절 삭제, 키를 뗐다가 다시 누르면 글자 삭제로 복귀합니다. 설정에서 끌 수 있습니다.

위 전환과 긴 Backspace 세 동작은 사용자의 실제 키보드에서 확인했습니다. Codex 자동 입력도 앱 재실행 후
정상으로 확인했습니다. 모든 앱·원격 클라이언트의 호환성을 보장하는 결과는 아니므로 아래 주의점과
[상세 검증 기록](VALIDATION.md)을 함께 확인하세요.

## 현재 버전과 원격 접속 시 주의

현재 버전은 메뉴 앱 **0.3.2** + 네이티브 입력기 **0.2.3**입니다.
0.2.3은 유효한 입력 위치가 없는 경우 원래 키를 통과시키는 보호와 연결 상태 진단을 추가했습니다.
진단은 원문·키코드·문서 범위 없이 프로세스 ID, Codex/기타/알 수 없음 구분, 처리 단계·누적 횟수를
`~/Library/Application Support/CapsFlow/ime-health.json` 한 파일에 덮어씁니다(권한 0600). 원격 전송은 없습니다.

입력기 교체 뒤 이미 열려 있던 Codex에서 문자 입력이 막히고 Esc/Backspace만 동작한 사례가 있었습니다.
이 Mac에서는 미전송 내용을 보관한 뒤 **Codex만 완전 종료·재실행**하여 정상 입력이 복구됐고,
입력기에도 Codex 조합·확정 호출이 들어옴을 확인했습니다. 이를 모든 환경의 원인/해결 보장으로 보지는 않습니다.

0.3.1은 직접 연결된 HID 키보드가 없어도 메뉴 앱의 키 이벤트 연결을 유지합니다.
나중에 로컬 키보드를 연결하면 기존 Caps→F18 매핑을 적용하고, 원격 클라이언트가 보내는
원래 Caps Lock(키코드 57)의 키 누름/뗌 또는 Caps 플래그 변화도 전환으로 처리합니다.
두 종류가 함께 도착하는 짧은 중복 패킷은 한 번만 처리하며, Caps 플래그만 보내는 클라이언트는
On/Off 두 방향 모두 전환합니다. 전환에 사용된 Caps의 대문자 잠금 영향은 제거하되 실제 Shift는 유지합니다.

원격 클라이언트가 Caps Lock을 서버에 전달하지 않으면 앱에서 감지할 수 없습니다.
이때 **⌃⇧Space(Control+Shift+Space)** 또는 설정창/메뉴의 **다음 입력 모드로 전환**을 사용하세요.
이 대체 동작도 Speed/3단계 설정을 따릅니다. 키보드 이벤트가 아예 전달되지 않는 환경에서는
메뉴에서 한글/English/자동을 직접 선택할 수 있습니다.

0.3.0에서는 키보드 부재가 전체 시작 실패와 입력 소스 재전환을 일으켰으며, 당시 메뉴 앱을 종료한
독립 입력기 상태에서 원격 Codex의 `dkssud` + Space → `안녕`을 사용자가 확인했습니다.
원격 Caps 처리의 자동 검사와 현재 사용자 키보드의 Caps/대체 단축키 동작을 확인했습니다.
키보드 0개 상태는 모의 서비스 목록으로 시작·감시·정리를 검사했습니다. 자세한 범위는 [검증 기록](VALIDATION.md)을 따릅니다.

## Backspace 길게 누르기 · 0.3.2

설정창의 **Backspace를 1초 이상 누르면 어절 단위 삭제**를 켜면(기본 켬), 처음 1초는
기존 글자 삭제를 유지하고 이후 반복 키에만 Option을 붙여 앱의 이전 단어 삭제로 전달합니다.
[macOS의 Option-Delete](https://support.apple.com/en-us/102650)는 커서 왼쪽 단어를 지우며,
실제 어절·구두점 경계는 사용하는 앱이 결정합니다. 자동 모드의 조합 중인 단어는 먼저 확정하고
앱의 삭제로 넘깁니다. 직접 문서를 읽거나 전체 문장을 덮어쓰지 않습니다.

- 키를 떼거나 다른 키·수정 키·마우스 클릭·앱/입력 모드 변경이 발생하면 즉시 초기화합니다.
- 기존 Option/Command/Control/Shift/Fn+Backspace, Forward Delete, 보안 입력과 제외 앱은 바꾸지 않습니다.
- 현재 키 반복 속도를 사용하며 추가 삭제 타이머나 합성 키 재생은 만들지 않습니다.
  메뉴 앱이 켜져 있고 키 반복 신호가 전달되어야 하므로, 반복 신호를 누락하는 원격 환경은 적용되지 않을 수 있습니다.
- 설정을 끄면 기존 Backspace 동작만 유지합니다. 네이티브 입력기 0.2.3 자체는 교체하지 않습니다.

- 수동 한글 선택은 해당 단어의 공백 확정까지 우선하여 자동 영어 판정이 덮어쓰지 않습니다.

## 0.2.0 · 한국어 우선 네이티브 입력기

이 Mac에 0.2.0을 설치·활성화했고, 사용자가 실제 Codex에서 Caps 순환, 한·영 확정,
오른쪽 Option 선택, 빠른 다문장 입력, 잠시 멈춘 뒤 한글 이어쓰기가 정상임을 확인했습니다.

`자동`은 이제 ABC 입력 후 지우고 재입력하는 보조 기능이 아니라, 별도 **CapsFlow 한국어 우선**
입력 소스입니다. [Apple InputMethodKit](https://developer.apple.com/documentation/inputmethodkit)의
조합/확정 API를 사용합니다. 자동 모드에서는 기존 AX 조회·백스페이스·합성 키 재생 경로를 사용하지 않습니다.

- 기본은 두벌식 한글 조합입니다. 사전 밖 단어·Shift·단독 자모도 한글로 유지합니다.
  `r`은 `ㄱ`, `QKfmrp`는 `빠르게`입니다.
- `hello`, `API`, 주소·이메일·단위처럼 명확한 영어만 단어 확정 시 영어로 복원합니다.
  `go/해`처럼 양쪽 해석이 있으면 한국어를 기본으로 둡니다. 코드/영문 장문은 EN 모드를 권장합니다.
- 애매한 입력의 영어 후보는 작게 표시합니다. 조합 중 **오른쪽 Option / ⌘⌥Z**로 한·영을
  명시 선택할 수 있습니다. 후보 위치를 입력란이 제공하지 않으면 팝업만 생략하며 단축키는 유지합니다.
- 잠깐 멈춰도 현재 조합은 유지합니다. 확정된 한글 뒤에도 새 한글을 자연스럽게 이어 입력합니다.
  공백·닫는 기호에서 현재 조합만 확정하고 오른쪽 기존 단어는 교체하지 않습니다.
- ⌘⌥Z는 선택 문장의 두벌식 자판 변환도 지원합니다. 한글 선택은 영타로, 영타 선택은 한글로
  바꿉니다(번역/맞춤법 교정 아님). 지원되는 클라이언트의 정확한 선택 범위만 사용하며,
  선택 내용/범위를 확인하지 못하면 교체하지 않습니다. 마지막 변환 원문 한 건만 메모리에 둡니다.
- 타속은 개인의 한국어 입력 대비 평균 간격만 사용합니다. 긴 생각/휴식 간격은 제외합니다.
  속도만으로 영어를 선택하지 않으며, 덜 흔한 영어 사전 단어 + 최근 영어 연속 입력이 함께 있을 때만 보조합니다.
  간격 평균과 현재 조합은 메모리에서만 처리하며 원문 로그·원격 요청은 없습니다.

구성: 메뉴/Caps Lock 담당 `~/Applications/CapsFlow.app` + 조합 담당
`~/Library/Input Methods/CapsFlowInputMethod.app`. 기존 macOS 두벌식과 ABC는 삭제하거나 수정하지 않습니다.

검사/빌드:

```sh
./scripts/test.sh
./scripts/build.sh
zsh ./scripts/build-input-method.sh
```

새 입력기 등록·활성화는 사용자의 승인을 받은 뒤 사용자 Library의 Input Methods에 설치하고
`CapsFlowInputMethod --register <설치한 앱 경로>`로 등록 요청합니다. enable API의 성공 반환만으로
활성화 완료로 보지 않습니다. 이 Mac에서는 재로그인 후 **시스템 설정 → 키보드 → 입력 소스 편집 →
추가 → 한국어 → CapsFlow 한국어 우선 → 추가**가 필요했습니다. 이후 메뉴에서 자동을 선택하거나
`--activate`로 선택합니다. 추가 목록에도 보이지 않으면 로그아웃/로그인 후 다시 확인합니다.
활성 세션에서 재설치하기 전에는
ABC/두벌식으로 전환해 조합을 확정하고 기존 입력기 프로세스 종료를 확인해야 합니다.

되돌리기: 입력 메뉴에서 **두벌식 또는 ABC**를 선택합니다. 메뉴 앱의 이전 설치본은
`dist/CapsFlow-before-0.2.0.zip`에 보관했습니다. 새 입력기 미선택 상태에서 이전 앱을 복원할 수 있습니다.
0.2.0의 실제 Codex·물리 키보드 검증 상태는 `VALIDATION.md`를 따릅니다.

설치 위치: `~/Applications/CapsFlow.app`

```sh
./scripts/build.sh

```

처음 실행하면 **접근성 권한 허용…** 버튼을 누르고 macOS 설정에서 CapsFlow를 허용한다. 시스템 버전에 따라 **입력 모니터링**도 허용해야 할 수 있다. 권한을 허용하면 앱이 이를 감지해 전역 입력 처리를 시작한다. 테스트창은 권한 없이 사용할 수 있다.

### 0.1.11 · 이미 쓴 문장 복구와 빠른 입력

- **자동 모드에서 잘못 친 영타 부분을 선택 → ⌘⌥Z**: 최대 4,096 UTF-16 길이의 여러 문장을

  자판 변환 대상입니다. 코드·주소·이메일·일부 기술 용어와 단위는 보존합니다.
- 선택하지 않은 앞뒤 텍스트는 교체하지 않습니다. 보조키를 뗀 뒤 같은 입력란·선택 범위·
  원문을 다시 확인하고 정확히 그 선택만 교체합니다. 읽기 전용/보안 입력란은 거부하며,
  AXValue 전체 덮어쓰기나 클립보드는 사용하지 않습니다.
- 적용 확인이 된 동일 부분을 다시 선택하고 ⌘⌥Z를 누르면 원문으로 복원합니다.
  마지막 선택 변환 한 건만 메모리에 두며 종료 시 지웁니다. 파일 기록/전송은 없습니다.
- 선택이 없으면 기존 추천 적용·직전 단어 판정 뒤집기가 유지됩니다. 오른쪽 Option은
  기존처럼 보이는 단어 후보 적용용입니다. 문장 전체 복구에는 선택+⌘⌥Z를 사용하세요.
- 한국어 문맥이 뚜렷하면 사전 밖의 불완전한 한글 조합에도 한국어 우선 점수를 부여합니다.
  알려진 영어 단어·코드·주소·단위·한 글자 영문 보호는 유지하며, 이미 한글로 잘못 쓴
  오타까지 의미적으로 교정하지는 않습니다.
- 보관한 일반 키 입력은 상태 추적 후 원래 앱으로 순서대로 직접 전달합니다. 이전처럼
  세션 이벤트 탭을 한 번 더 비동기로 돌아오면서 새 입력과 섞이는 경로를 제거했습니다.
  시스템 수정 키/단축키는 세션으로 전달하여 기본 한/영 전환 등 시스템 동작을 보존합니다.

- **작은 한글 추천창 (0.1.4)**: 자동 모드에서 약 160ms 입력을 멈추면 커서 위에 두벌식 한글 후보를
  보여줍니다. 자동 변환하지 않은 단어는 스페이스 확정 후에도 후보를 보여줍니다. **⌘⌥Z로 명시적으로 적용**하고
  Esc로 닫습니다. 추천창은 포커스·마우스를 가로채지 않으며 다음 입력·커서 이동·앱 전환 시 숨깁니다.
  커서 좌표를 제공하지 않는 입력란에서는 해당 입력란 상단에 표시합니다. 0.1.5부터 후보 생성은 자동 판정과
  분리합니다. 자동으로 한글이 된 단어는 중복 표시하지 않고, 영단어·개발 용어로 보존한 입력에도 문자 그대로의
  두벌식 후보를 보여줍니다(자동 적용하지 않음). URL·이메일·경로·중간/끝 숫자 혼합·보안 입력은 제외합니다.
  0.1.9부터는 숫자 접두어 뒤 영타에도 같은 후보 정책을 적용하며 숫자는 보존합니다.
  후보는 맞춤법 교정이 아닌 자판 변환입니다. 최대 30초 표시하며 입력/커서/포커스 변경 시 즉시 숨깁니다.
  ⌘⌥Z를 누른 뒤 보조키를 모두 떼면 현재 입력란과 원문을 다시 확인하고 적용합니다.
  **0.1.6부터 오른쪽 Option(⌥) 단독 탭으로도 후보를 적용**합니다. 후보가 보일 때
  0.6초 이내로 눌렀다 떼는 경우만 처리합니다. 다른 키/수정 키와 조합하거나 길게 누르면
  적용하지 않으며, Option의 원래 수정 키 이벤트는 그대로 전달합니다.
  후보가 없거나 왼쪽 Option을 누른 경우에는 이 동작을 하지 않습니다.
  0.1.7에서는 후보 적용 직후 스페이스 없이 영타를 이어도 다시 후보를 표시합니다.
  직전 CapsFlow 적용 위치·입력란·실제 원문이 일치하는 경우에만 이어쓰기 경계를 인정하며,
  기존 영문 단어·식별자의 일부를 임의로 바꾸지는 않습니다. 커서나 앱을 옮기면 이 연결은 해제됩니다.
  0.1.8에서는 스페이스 전후 AX 갱신 지연을 제한 시간 내 재시도하며, 설정창의 ‘최근 조회 실패’에는
  실패 조건만 표시합니다. 입력 내용·키 이력은 기록하지 않고 진단 상태를 디스크에 저장하지 않습니다.
  후보가 없는 경우 ⌘⌥Z는 기존처럼 직전 확정 단어를 뒤집습니다. 설정창의 ‘추천 미리보기’로 모양을 확인할 수 있습니다.
- 메뉴바에서 현재 앱을 자동 변환 제외 목록에 추가/제거 가능

## 판정과 문맥

한·영 빈도 목록 각 5만 단어, 두벌식 조합 가능성, 반복 자모·채팅 표현을 함께 사용한다. 비문을 교정하지 않고, 입력 자판의 의도를 추정해 철자·반복을 보존한다. 모든 비표준 표현을 인식하는 범위는 아니다.

양쪽 후보가 유효해 한글 판정 점수가 45–55점인 경우 **현재 입력란에서 커서 앞 두 문단, 최대 2,000자**를 참조한다. 문맥 점수는 한·영 문자 분포와 현재 문단의 최근 부분에 가중치를 주어 계산한다. 문맥이 부족하면 최근에 판정한 언어를 유지한다. 화면의 0–100점은 휴리스틱 순위 점수이며 통계적으로 보정한 확률이 아니다. 혼용 문장의 의미에 따라 고유명사와 일반 단어를 구분하는 정확도에는 한계가 있다.

문맥은 단어 확정 시 macOS Accessibility API에서 읽는다. **커서 앞 원문이 실제 입력한 단어와 일치하고 선택 영역이 없을 때만** 교체한다. AX로 입력란 내용이나 커서를 확인할 수 없으면 원문을 유지한다. 보안 입력이 켜진 비밀번호 창에서는 전역 이벤트를 처리할 수 없다. 앱별 호환성은 실제 입력란에서 확인해야 한다.

문맥 조회와 판정은 이벤트 콜백 밖에서 실행한다. 처리 중 입력은 순서대로 보관했다가 재생하며, 지연이 길면 원문으로 통과시킨다. 마우스 클릭이나 앱 전환 시 버퍼를 비운다. 입력 기록을 디스크에 저장하지 않고 네트워크로 보내지 않는다. 클립보드를 사용하지 않는다.

## Caps Lock과 복구

### 0.1.1 입력란 호환성 및 반응 개선

- Electron/Chromium 앱은 자동 모드에서 활성화될 때 `AXManualAccessibility`로
  입력란 접근성 정보를 준비합니다. 최초 단어를 확정할 때 뒤늦게 준비하느라
  변환을 놓치는 경우를 줄입니다. 현재 포커스 입력란과 그 텍스트 조상만 조회하며,
  페이지 전체나 다른 입력란을 탐색하지 않습니다.
- 0.1.3에서는 macOS 기본 한/영 단축키·입력 메뉴·앱별 입력 소스 복원을 존중합니다.
  자동 모드에서 두벌식으로 바뀌면 한글 모드로 따라가며 ABC로 강제로 되돌리지 않습니다.
  다시 자동 모드를 쓰려면 Caps Lock 순환 또는 모드 선택을 사용합니다.
- Caps 키를 누를 때 입력기 목록을 매번 열거하지 않고 캐시합니다. 입력기 추가·삭제 시
  캐시를 비우며, EN ↔ 자동처럼 이미 올바른 자판이면 입력기 재선택을 생략합니다.
- 보안 입력란·선택 영역·원문/커서 불일치는 여전히 변환하지 않습니다. 문맥 조회를
  우회하거나 클립보드·네트워크로 텍스트를 보내는 방식은 사용하지 않습니다.
- 로컬 ad hoc 서명 앱을 업데이트하면 기존 접근성 스위치가 켜져 있어도 새 바이너리를
  허용하지 않을 수 있습니다. 이때 설치된 앱의 접근성 및 입력 모니터링 승인을 갱신하고
  CapsFlow를 다시 실행해야 합니다.

### 0.1.3 키 누름 권한 검증 및 기본 한/영 복구

- 이벤트 탭 생성 성공만으로 동작 중이라고 표시하지 않습니다. macOS가 실제 등록한
  이벤트 마스크에 키 누름·뗌·수정 키 변화가 모두 있는지 확인한 뒤 Caps Lock을 매핑합니다.
  입력 모니터링 승인이 유효하지 않아 키 누름이 제외되면 매핑하지 않고 오류를 표시합니다.
- 실행 중에도 연결을 검사하며 키 이벤트 연결이 사라지면 원래 Caps Lock 매핑을 복원합니다.
- 입력 소스 선택 전에 새 모드를 반영하여 한 → EN → 자동 순환 중 입력기 변경 알림이
  이전 모드로 되돌리는 재진입도 방지합니다.

Electron의 공식 지원 방식:
[Accessibility](https://github.com/electron/electron/blob/main/docs/tutorial/accessibility.md).

실행 중에는 공개 IOKit API로 Caps Lock만 F18로 매핑한다. 기존의 다른 키 매핑은 유지한다. 키보드를 새로 연결하면 매핑을 적용한다. 정상 종료 시 원래 Caps Lock 매핑을 복원한다. 별도 감시 프로세스가 앱의 비정상 종료도 감지해 복원한다.

복구용 JSON에는 프로세스 식별자와 원래 키 매핑만 들어간다.

```sh
~/Applications/CapsFlow.app/Contents/MacOS/CapsFlow --recover-caps
```

실행 중인 앱의 매핑은 위 명령으로 해제하지 않는다. 메뉴바에서 먼저 종료하거나 일시 정지한다.

## 검증 및 진단

이 작업의 대상 환경은 Apple Silicon / macOS 27.0.1 / Swift 6.4 Command Line Tools다. 전체 Xcode 없이 빌드할 수 있다.

```sh
./scripts/test.sh
swift scripts/check-running.swift
./dist/CapsFlow.app/Contents/MacOS/CapsFlow --diagnose
./dist/CapsFlow.app/Contents/MacOS/CapsFlow --evaluate go --context '오늘 할 일을 정리했어. 이제 시작을 '
./dist/CapsFlow.app/Contents/MacOS/CapsFlow --evaluate go --context 'We are ready. Let us '
```

`test.sh`는 두벌식의 모든 완성형 11,172자 왕복 변환, 일반 어휘, 반복 자모, 문단별 중의성, 기술 문자열 보존을 검사하고 AppKit 테스트창에서 실제 편집 동작을 검사한다. 전역 이벤트 처리·입력 권한·다른 앱에서의 입력 호환성은 별도의 실행 검증 항목이다.

`check-running.swift`는 실행 중인 앱의 실제 macOS 이벤트 마스크를 확인합니다.
`keyboardReady: true`는 키 누름·뗌·수정 키 이벤트의 연결 확인이며 물리 키나 입력란 변환의
성공 판정은 아닙니다. 키 입력·화면 텍스트를 읽지 않고 권한도 요청하지 않습니다.

소스 구조:

- `Sources/InputCore`: 두벌식 조합, 빈도 사전, 언어·문맥 판정
- `Sources/CapsFlow/EventEngine.swift`: 전역 이벤트, 지연 처리, 커서 검증, 교체·복구
- `Sources/CapsFlow/AccessibilityContext.swift`: 현재 입력란 문맥 조회
- `Sources/CapsFlow/CapsKeyMapper.swift`: Caps 매핑, 기존 매핑 보존, 비정상 종료 복구
- `Sources/CapsFlow/AppDelegate.swift`: 메뉴바·설정·테스트창
- `Tests/InputCoreTests`: Command Line Tools만으로 실행하는 검증 프로그램

개발용 앱은 로컬 ad hoc 서명을 사용한다. 바이너리를 다시 빌드해서 교체하면 macOS에서 접근성 권한을 다시 허용해야 할 수 있다.
